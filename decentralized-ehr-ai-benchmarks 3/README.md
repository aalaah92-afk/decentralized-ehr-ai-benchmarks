# decentralized-ehr-ai-benchmarks

Reference implementation, tests and security-analysis artefacts for the manuscript
*"Patient-centric blockchain/IPFS framework for digital-radiography EHR sharing with auditable AI inference"*
(MDPI *Computers*, revised submission).

Everything the manuscript reports about the smart contract and the off-chain cryptographic protocol
is regenerated by one command, `./run_all.sh`, which writes raw execution logs to `logs/`.

## Reproducing without installing anything (GitHub Actions)

1. Create a public GitHub repository named `decentralized-ehr-ai-benchmarks` and upload all files of this
   folder (GitHub Desktop, or the web page *Add file → Upload files*; if the hidden `.github` folder is not
   uploaded, create `.github/workflows/reproduce.yml` via *Add file → Create new file* and paste its content).
2. The push starts the **reproduce** workflow (tab *Actions*). It compiles and tests the contract, runs the
   gas/throughput/latency benchmarks, Foundry fuzz + invariant tests, Slither, Mythril, a real IPFS (Kubo)
   benchmark, the off-chain tests and the simulations.
3. When it finishes, the raw logs are committed to `logs/ci/` together with `PROVENANCE.md`, which links to
   the exact workflow run. Cite that run URL in the manuscript.
4. Optional Sepolia measurements: add repository secrets `SEPOLIA_RPC_URL` and `DEPLOYER_PRIVATE_KEY`
   (testnet-only key from a faucet) and re-run the workflow.

```bash
# Node >= 18
npm install
npx hardhat compile
npx hardhat test                      # lifecycle, revocation and adversarial tests
REPORT_GAS=1 npx hardhat test         # + logs/gas-report.txt

# full reproduction with logs (also runs Foundry, Slither, Mythril when installed)
./run_all.sh
```

## Protocol summary

```
P                      serialized DICOM payload
H_P = SHA-256(P)                                   image-identity commitment (on-chain)
K   <- CSPRNG(256 bit), fresh for every record version
IV  <- CSPRNG(96 bit),  fresh for every encryption
(C, T) = AES-256-GCM_K(IV, P)
bundle = C || IV || T  -> IPFS -> CID
H_C = SHA-256(C || IV || T || CID)                 ciphertext-integrity digest (on-chain)
sig = ECDSA-secp256k1( EIP-712 RecordAttestation{patient, recordId, version, CID, H_P, H_C, timestamp} )
      domain = {name:"EHRRegistry", version:"1", chainId, verifyingContract}

ECIES wrap for clinician c (public key checked against c's address: address = keccak256(PK)[12:]):
  r <-R Z_q*, R = rG (33 B compressed);  S_x = x(r · PK_c)
  K_wrap = HKDF-SHA256(ikm = S_x, salt = R, info = "EHR-Key-Wrap", L = 16 B)
  (C_key, T_key) = AES-128-GCM_{K_wrap}(IV_wrap, K, AAD = recordId || version || address_c)
  WK_c = R || IV_wrap || C_key || T_key  (93 B) -> stored on-chain in wrappedKeys[patient][recordId][version][c]

AI inference: Vector_AI = 14 × float32 (big-endian), Salt = 32 random bytes
  Hash_infer = SHA-256(Vector_AI || Salt)            (on-chain commitment)
  AES-256-GCM(Vector_AI || Salt) -> IPFS -> CID_infer (on-chain pointer)
  clinician signs EIP-712 DiagnosticAuthorization{patient, recordId, recordVersion, Hash_infer,
      CID_infer, modelVersionHash, clinician, permissionEpoch, nonce, deadline}; any relayer may submit
```

## What revocation enforces (and what it cannot)

| After `revokeAccess(recordId, clinician)` | Enforced by |
|---|---|
| `getRecordKey`, `getRecord`, `getInference` revert for the clinician | contract (interface policy) |
| AI commitments signed by the clinician are rejected, including authorizations signed before revocation (epoch bump) | contract |
| Wrapped key for the current version deleted from current state | contract |
| No wrapped key can be published for the clinician for any later version (`AccessNotGranted`) | contract |
| Later versions are encrypted under fresh keys the clinician never receives → direct IPFS retrieval yields undecryptable ciphertext | cryptography (tested in `02_revocation.test.js`) |
| **Not enforceable:** plaintext or keys of earlier versions the clinician already obtained (historical wrapped keys also remain in chain history) | out of scope — requires DLP / TEE controls |

## Confidentiality boundary

All contract storage, event data and transaction inputs are public to every node operator, regardless
of Solidity `private` or view-function access checks (any caller can choose `from` in `eth_call`).
The contract therefore holds only CIDs, digests/commitments, ECIES-wrapped keys (ciphertext),
permission flags, versions, epochs, addresses and timestamps. Confidentiality rests on AES-256-GCM and
ECIES, not on contract access control. Metadata (addresses, timing, call frequency, CIDs) remains visible.

## Scope of this repository

Implemented and tested: the smart contract, the off-chain cryptographic protocol, Shamir key escrow,
stealth recipient addresses, relayed (gas-abstracted) submission of AI commitments, and the
benchmark/security harnesses. Design only (not implemented): ERC-4337 bundler/paymaster infrastructure,
Merkle batching of state updates, on-chain auditing of key-recovery requests. Measurements are only those
written to `logs/` by the scripts; `logs/README.md` states where each log was produced. The DenseNet121
results require the NIH/CheXpert images or the saved prediction files (`ai/README.md`).
